# Desktop disruption during packaging validation

## Evidence

On 2026-09-25 a local test started the `served-pkg-debug` Docker container with
`--privileged`, private cgroups and systemd as PID 1. Host journal timestamps (+08:00):

- 21:50:11: the debug container started.
- 21:50:12: host logind re-established input-device watches.
- 21:50:14: the desktop session logged out.

The timing strongly implicates the test. The exact device operation that caused the
session logout has not been established. It would be incorrect to claim that a
privileged container is sufficiently isolated from host devices because it uses a
private cgroup namespace or mounts no explicit device paths.

## Containment

The container exited. Its available logs and selected state were saved locally under
`out/incident/`, and the stopped container was removed by name. No global cleanup or
desktop configuration change was performed.

## Corrective measures

- Local verification contains no Docker, package install or system service operations.
- The build image defaults to bash, not systemd.
- All containers run in GitHub-hosted disposable CI VMs. Full systemd testing may use
  a privileged container there; the VM is the outer isolation boundary.
- CI entrypoints refuse local/self-hosted use before invoking Docker or package tools.
  Environment checks are accident prevention, not an unforgeable sandbox.
- Tests verify those refusals using mocked dangerous commands; hook failure tests use
  mocked systemctl and cannot operate real services.
- The systemd job waits for a usable control interface, captures diagnostics and has
  time limits. Publication remains blocked until it succeeds.
